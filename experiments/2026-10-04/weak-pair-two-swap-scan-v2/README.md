# Scope and start

This prepares one root-owned bounded two-block replacement scan from the checked
64-block H12/D29 family, SHA256
`44e0ee69fb32f37eed00955e25c699a72430d85871ca03a348c0bf572edb7a0a`.
It has 12 uncovered triples, per-pair maximum deficit sum 29, expanded deficit
sum 29, pair minimum 5, zero single and quadruple deficits, and named core
overlaps `[1,1,1,2]`. Preparation does not launch the optimization pass.

All 4,368 blocks retain global lexicographic order and 1-based point labels.
Internal block IDs are zero-based. Choose removals B<C among the original 64
and additions A<D among the 4,304 blocks outside the ORIGINAL family. The shell
has `C(64,2)*C(4304,2) = 18,668,272,896` distinct neighbors. The driver visits
2,016 removal pairs and 4,304 first additions for each: 8,676,864 outer states.
Even the last first-addition ID, which has zero possible greater additions,
is included in these outer-state counters.

Every two-block replacement has unique removed set `original minus neighbor`
and added set `neighbor minus original`. Sorting each pair gives exactly one
B<C, A<D tuple in these loops. Conversely every such tuple gives exactly that
neighbor. Additions never reintroduce removed original blocks, so one-block
moves and the unchanged initial family are outside this exact two-swap shell.

# Complete pair-floor pruning

After removing B,C and adding A, let `delta(P)=5-count(P)` for each pair P.
One remaining block can increase any pair count by at most one. If any delta
exceeds one, no final addition is possible. Otherwise define U as the union
of endpoints of every pair with positive delta. A final block D repairs every
positive delta if and only if it contains U. Indeed containment includes each
required pair, and necessity follows because D must include both endpoints of
every deficient pair. If U has more than five points, no five-point block can
contain it. If U is empty, every originally absent D>A is a pair-floor completion.

For each universe block, all 32 submasks are added to a mask-to-supersets index,
including mask zero. This produces 139,776 incidences in sorted block order.
For a possible support, enumerating every indexed superset D outside the
original family with D>A is thus necessary and sufficient for the pair floor.
It makes no additional assumptions about the starting design or incidence
shape. No intermediate coverage, single-row, quad-row, or core-cap rejection
is applied: the second addition may repair such a violation.

# Final rows, rank, and exact rollback

The reused `kernel.hpp`, `cores.hpp`, and `scan.hpp` are byte-identical to the
independently audited one-swap producer. A completed neighbor must have 64
distinct blocks, all 120 pair counts at least 5, all 1,680 single rows
`13-3*c(P)+c(P union {a}) <= 0`, all 10,920 quadruple rows
`12-3*c(P)+2*c(P union {a,b}) <= 0`, and overlap at most 55 with each of the
same four named cores. There is no hard D2zero, profile, symmetry, regularity,
new core, or extra holes restriction.

The rank is lexicographic `(holes,D2max)`, where D2max is the sum over pairs of
the maximum positive stronger-row deficit for that pair. The expanded sum of
all 10,920 stronger-row deficits is reported as D2sum separately.

Only row groups for pairs contained in at least one of B,C,A,D are recalculated,
including intersection pairs with net pair-count delta zero. If a pair, triple,
or quad count occurring in a row indexed by P changes, that subset is contained
in a changed block and contains P. Thus P lies in this union; row groups outside
the union stay at their verified baseline values. Holes and core overlaps are
updated separately. Each final-addition evaluation restores the 63-block state;
then A is removed and B,C restored. Direct recounts occur every 4,096 evaluated
neighbors, every 4,096 completed outer states, and at exit. Final selected IDs
must equal the original IDs. Invalid phases and IDs reject before mutation.

# Accounting and bounded output

All shell counters use unsigned 64-bit integers. For each started outer state,
the driver counts all D>A before pruning, the exact number generated by the
support rule, and their difference as pair-floor-pruned neighbors. It then
evaluates generated completions one by one. At every saved final state:

- `accounted = pair_floor_pruned + evaluated`;
- `eligible_generated = evaluated + pending_eligible`;
- `pair_floor_pruned + eligible_generated` equals the exact shell size covered
  by the started outer states;
- started minus completed outer states is zero or one.

The started-shell size for n outer states is
`floor(n/4304)*9,260,056 + r*(8607-r)/2`, where `r=n mod 4304`.
Support bins distinguish deficit greater than one, support size greater than
five, and support sizes zero through five. Separate shell-size bins make
pruning volume visible. Pruning is not reported as full metric evaluation.
On an interruption, untested generated completions remain pending and are not
included in accounted. Accounting is not necessarily an initial consecutive
prefix of shell ordinals because all pruned completions of the active outer
state are accounted before its generated completions are evaluated.

Completed means all 8,676,864 outer states completed, with accounted equal to
18,668,272,896 and no pending completions. A timed-out or interrupted run is
explicitly incomplete, even if the final zero-tail outer state was not reached.
The seedless pass checks a 120-second limit before each outer state and each
final evaluation. The wrapper has a 135-second watchdog and five-second
termination grace. There is no relaunch, second pass, or budget transfer.

Every strict improvement is logged. Every final best tie strictly better than
the starting rank is saved by its sorted outgoing/incoming pairs and exact full
shell ordinal. No ties when the initial rank remains best is valid. The Python
recorder reconstructs every distinct saved family, independently recounts its
rows and rank, verifies it with both the package checker and standalone parser/
verifier, and stores its full family SHA256 and compact receipts. It saves one
full representative and checks it again through the standalone CLI. Full-shell
ordinals are distinguished from actual evaluated-neighbor counters.

A complete scan settles only this restricted two-swap neighborhood. An
incomplete scan reports only the observed best result. Neither proves general
nonexistence or a global covering-number lower bound.
